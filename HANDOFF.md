### 1. How the game is put together now (what a new session needs to know)
**Scenes and input (`public/scenes.js`)** — scenes `menu · stable · office · farm · race`, derived from `ui.state` (`show()` → `SCENES.sync`). Hooks: `SCENES.register(name, {enter, leave})` fire only on scene *transitions*. The farm file registers **two**: `"farm"` (walking) and `"menu"` (the menu-background showcase). Input contexts `race | farm | ui`. `SCENES.enter("farm"|"career"|"menu", {instant})`. Career screens (`c_*` ui states) are the *stable* scene (STABLE3D) or *office*; they are HTML over a 3D backdrop and are entered/left through `CAREER.*` functions.
**The farm (`FARM`, `public/farm*.js`)** — one world, two uses:
- *Showcase* (`FARM.showcase`): background of main menu/Quick-Race-select/settings/how-to. Started ~60 ms after page load (`boot()` in farm.js) and by the `menu` enter hook; camera drift, boxes show `CAREER.farmStalls()` (only if `CAREER.hasSave()`, else five roster horses — it must never create a save), `FARM.setShowHorse(def)` is called from `setMenuHorse()` in index.html.
- *Walking* (`FARM.active`, ui.state `"farm"`): `FARM.enter()` builds once and keeps the world (`built`), per visit it re-stands horses/plaques (`stand()`/`unstand()`), binds its own capture-phase listeners, and restores `resume` (back from a career screen) or `P.arrive` (set by `FARM.arrive("hardstand")` after a race).
- Frame dispatch is in `frame()` in index.html: `ui.state==="farm" && FARM.active` → `FARM.frame(dt)`; menu states with `FARM.showcase && !race` → `FARM.frame(dt)`.
**Places:** `place` is `"out"` (`fscene`, the property, `world = FARMGROUND.assemble()`) or `"in"` (`iscene`, the farmhouse, built lazily by `FARMHOUSE.build()` → `iworld`). Both share `fcam`, the walker `P {x,y,z,face,speed}` and the camera state `CAM {yaw,pitch,dist,cur}`. Switching uses `startTrans(dur, mid, done)` (fade; `mid` runs when black). `cur()` returns the current place's world object (colliders/segs/points).
**Walker + camera (`farm.js`):** `collide()` = circle (PR 0.45) vs AABB `colliders` and capsule `segs` (fences), plus bounds (outside ±110×±80, inside the room bounds). Movement is camera-relative; walk 2.4 m/s, run 5.2, eased. `person` 1|3 (`settings.person`, V key, `ff_person`); FP eye 1.62 m, fov 72; TP orbit from `CAM.dist` (4.6; 3.4 max inside) with `placeCamera()` marching inward until `blockedAt(x,y,z)` is false (colliders under 3.4 m, ground, room bounds). Look: pointer-lock click or drag (`look()`, `settings.lookSens` 0.5–2, `settings.lockMouse`), ← → keys. Esc → `escape()` → closes a panel, skips a trip, else toggles the pause overlay (Resume / Career hub / Main menu); pointer-lock release also opens it.
**Interaction points (the Phase 6 hook):** `world.points` (outside, from `farm-build.js`: `office` = farmhouse door, `travel` = the float) and `iworld.points` (inside, from `farm-house.js` + `door` added in `ensureHouse()`: `board, ledger, cabinet, mirror, door`). A point is `{id, x, z, r, text}`; `nearest()` picks the closest within `r`; the prompt text is `pointText(p)` (dynamic for `travel`); `interact()` dispatches on `p.id` — **add new ids there**. There is no facing / line-of-sight test yet (the spec asks for it in 6.1: add it in `nearest()`/`interact()` using the collider proxies — do not add a second system).
**Panels (`FARMUI`, `farm-ui.js`):** HTML drawn into `#farmPanel` over the farm. `FARM`'s `ctx` object (also `FARM._test.ctx`) is what panels and the trip are given: `panelEl, hud, scene, world, cam, fig, P, CAM, horses, sunFollow, mkHorse(def), fade(a), closePanel, refreshBoard, refreshFigure, setPrompt, skipHint, objective, heightAt, endTrip, setPlace`. New panel: add a name in `openPanel(name)` (farm.js) and a function in `FARMUI` that fills `ctx.panelEl`; Esc closing/`closePanel()`/`onClose` are already handled; movement is blocked while `panel` is set.
**Trip (`FARMTRIP`, `farm-trip.js`):** the float+ute are a separate group `world.structures.rig` (hinged ramp = `rig.userData.ramp`, rotation.z 0.296 down … −π/2 up). Phases `fadeIn, lead, shut, walk, drive, out`; ends by calling `CAREER.startBooked()`. It builds a *new* horse mesh (`ctx.mkHorse(booking.def)`) and hides the box horse with the same `userData.hid`.

### 2. Character interface (`FARMPEOPLE`, `farm-people.js`)
`make(app)` → `o {A, root, body, parts{pelvis,torsoG,neckG,headG,legL,legR,armL,armR}, mats, dressed, phase, speed, idleT, apply(app)}`; `pose(o, dt, speedMps)` (walk < 3.4 m/s, jog above; the phase only advances while moving); `dispose(o)`; `disposeShared()`. Appearance `A = C.player` = `{look{head 0–9, hair 0–9, hairCol, skin, build −1…1}, outfit "stable"|"training"|"raceday", colours{shirt,trousers,boots}}`; `CAREER.setPlayer(patch)` merges, validates through `CORE.cleanPlayer`, saves; then call `FARM._test.ctx.refreshFigure()` (= `fig.apply(appearance())`). ~29–34 meshes (≈29 draw calls). `apply()` rebuilds only the clothes (shared geometry, materials disposed) — verified leak-free. The model faces **+z** at rotation 0; the farm sets `root.rotation.y = π − face` (face = atan2(dx, −dz)). **There is no arm/hand pose for tasks yet** — grooming/feeding/leading animations need a small "task pose" layer on `pose()` (arm shoulder/elbow joints are `parts.armL.sh/.el`, `armR`), not a new character.

### 3. Horses on the farm (what exists to build interactions on)
- `CAREER.farmStalls()` → `[{def, name, sub, line2, line3, line4}]` (+`.slots`); `def` = `toDef(h)` (the *same* def the race uses, with `_hid` = horse id, `_sid:"player"`).
- `FARM.stand()` puts `buildHorse(def,0)` (rider hidden by `hideRider`) in each box: `g.position (spot.x±0.1, 0.15, spot.z+0.55)`, `rotation.y ≈ −π/2` (faces the courtyard); `userData.stallI` (box index), `userData.hid`, `userData.idleT`. Idle animation: `animateHorse(g,0,0,0,0,0,0,dt,null)` only for horses within 38 m of the camera (`animateNearHorses`). Horse walking: `PRESENT.animateWalk(g, phase, dt, {rest:1})` (phase advances `speed·dt/1.75`); horse model faces **+x** at rotation 0 (heading (dx,dz) → `rotation.y = atan2(−dz, dx)`).
- `world.stalls[i] = {x, z, door, plaque}` (box centre x, front z, door and plaque positions); five boxes at x = −8, −4, 0, 4, 8; the stable block is one big collider, so horses cannot be walked into — **interaction with a horse = an interaction point at each box front** (`{id:"horse0".. , x: stall.x, z: -21.4, r:1.6}`), not collision with the horse. Plaques are canvas textures per visit (`plaque()`); re-render on state changes.
- Career horse data (all in `C.horses[i]`, from Phase 2, `career-core.js`): `fitness 0–100` (recovers via `CORE.advance`), `composure 0–100`, `lastRaceDay`, `trainDay`, `trainedToday`, `plan`, `age`, `growth`, `acquired`, `retired`, `value`; `h.attrs/pot/lvl/xp/trainPts/history/...`. **None of `fitness/composure/plan` changes race behaviour today** (data + display only; the penalty helper `fitnessPenalty` exists in `CORE` but is not hooked). The existing hub screens (`CAREER._test.openProfile / openTraining / openStable / openTrophies`) are the "inspect" content to reuse.

### 5. Performance constraints (measured)
- Budget: **≤ 250 draw calls and ≤ 500k triangles** in every farm view (`tests/farm-browser.js` enforces it). Measured at the end of Phase 5: whole-property overview **249 calls**, 261k tris; typical views 74–181 calls. **There is no headroom at the overview** — any new always-visible mesh must be paid for (merge into an existing `Batch`, reuse a material, or share a cell); prefer interaction markers drawn as HTML or as one instanced/merged mesh. The walker costs ≈29 calls; the farmhouse interior is a separate scene (a few dozen merged meshes, only drawn while inside — measure before adding to it).
- The property builds once (~1 s on a fast machine); farmhouse ~50 ms; the menu showcase keeps the whole farm resident (geometry/textures stay allocated while on the menu: deliberate; `FARM.dispose()` frees it).
- Software GL (the test renderer) runs the farm at ~1–2 fps: browser tests count frames, not seconds, and stub `renderer.render` for logic tests (see `tests/farm-flow-browser.js`).

## What it is
A browser-based 3D horse-racing game (Three.js r128) with a realistic skill-based racing engine. Single-player ships as one
self-contained HTML file; an optional Node server adds online multiplayer. Procedural horses/jockeys/tracks/stable, no assets.
